# Data Model: Supabase Integration

**Feature**: `001-supabase-integration` | **Date**: 2026-11-24

This feature creates **no database tables**. The `public` schema stays empty; catalog, accounts,
scores and favorites get their own specs. The "entities" here are configuration and code-level
shapes.

## SupabaseConfig (result of reading the environment)

Produced by `lib/supabase/config.ts` from `process.env`. Discriminated union:

| Variant     | Fields                                   | When                                            |
| ----------- | ---------------------------------------- | ----------------------------------------------- |
| `ok: true`  | `url: string`, `publishableKey: string`  | both public variables present and valid         |
| `ok: false` | `missing: string[]`, `invalid: string[]` | any public variable absent, empty, or malformed |

Validation rules:

- `NEXT_PUBLIC_SUPABASE_URL` MUST parse as an absolute `http:` or `https:` URL (`http` allowed only
  for `localhost`/`127.0.0.1`, i.e. the local stack). Trailing slash is stripped.
- `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` MUST be non-empty. Keys starting with `sb_secret_` are
  rejected as `invalid` (a secret key placed in a public variable would leak to the browser).
- Values are read with static `process.env.NEXT_PUBLIC_…` access so Next.js can inline them.

## Clients

| Entry point            | File                                     | Returns                            | Lifecycle                                                                            |
| ---------------------- | ---------------------------------------- | ---------------------------------- | ------------------------------------------------------------------------------------ |
| `getServerSupabase()`  | `lib/supabase/server.ts` (`server-only`) | `SupabaseClient<Database> \| null` | new stateless client per call; `persistSession: false`, `autoRefreshToken: false`    |
| `getBrowserSupabase()` | `lib/supabase/client.ts`                 | `SupabaseClient<Database> \| null` | one lazily created `createBrowserClient` (`@supabase/ssr`) singleton per browser tab |

`null` means "not configured"; callers fall back to `lib/data.ts`.

## Database (generated types)

`lib/supabase/database.types.ts`, generated by `npm run db:types` from the local stack. With an
empty `public` schema it contains the `Database` type with no tables; it is regenerated whenever a
migration is added.

## Migration

Versioned SQL file under `supabase/migrations/<timestamp>_<name>.sql`. Ordered by timestamp,
applied by `db:reset` locally and `db:push` remotely. None are created in this feature. Rule for
future migrations (FR-012): every new table enables Row Level Security in the same migration that
creates it.
